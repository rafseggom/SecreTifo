# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase:** 1 — Flujo completo del amigo invisible (SecretKit)
**Design system:** none — greenfield, plain Tailwind v4 + native `<dialog>`
**Language of user-facing copy:** Spanish (es-ES). Technical names, props, tokens and file names stay in English.
**Pre-populated from:** `01-CONTEXT.md` (D-01…D-25), `01-RESEARCH.md`, `REQUIREMENTS.md`, `ROADMAP.md`. User input was required for exactly two fields (design-system tool, accent hue) — both answered as recommended.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable — greenfield; no `components.json`, no `package.json`, no `src/` (verified 2026-10-17: repo contains only `LICENSE`, `AGENTS.md`, `.planning/`) |

**Component Inventory is intentionally omitted** — the template's rule is to omit it entirely when `Tool: none`. Its role is filled by `## Component Contracts` below, which names the exact primitives this phase hand-rolls. `## Registry Safety` is retained and marked not-applicable.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `p-1` | Gaps inside a label/helper pair, badge horizontal padding |
| sm | 8px | `gap-2`, `p-2` | Gap between a control and its helper text, vertical padding of a list row, minimum gap between adjacent tap targets |
| md | 16px | `gap-4`, `p-4` | Default stack gap, mobile page gutter, card padding on `<sm` |
| lg | 24px | `gap-6`, `p-6` | Gap between form sections, card padding on `≥sm` |
| xl | 32px | `py-8`, `gap-8` | Page top padding, gap before the sticky primary CTA |
| 2xl | 48px | `py-12` | Major section break (e.g. between "Sus preferencias" and "Tu pedido" on `/reveal`) |
| 3xl | 64px | `py-16` | Page-level breathing room, `≥sm` only — never on a 320px viewport |

Exceptions: 12px (`gap-3`, `py-3`) is permitted inside the size-guide card/table cells and for list-row vertical padding — it is a multiple of 4 even though it is not one of the seven declared tokens.

Size constraints (not spacing tokens, but binding):

- **Minimum interactive target: 44×44px** (`h-11`, `min-w-11`). Applies to every button, the modal close button, the download control and each `Select`.
- **Page gutter:** 16px on `<sm`, 24px on `≥sm`.
- **Content shell:** `max-w-md` (448px) centred on `≥sm`, so the mobile-first column never stretches into a wide, hard-to-scan layout.
- **Sticky CTA clearance:** scroll containers that carry a sticky bottom action reserve `pb-24` (96px) so the last row is never covered.
- Maximum content width for prose blocks: `max-w-prose` inside the shell — never full-bleed text at 448px.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Weights: exactly two — 400 regular (`font-normal`) and 600 semibold (`font-semibold`).** 500 (`font-medium`), 700 (`font-bold`) and 800 are forbidden in this phase.

Allocation rules (which role goes where — no discretion left to the executor):

| Role | Applied to |
|------|-----------|
| Display (28/600/1.2) | Exactly two places in the whole phase: the app name on `/` and the reveal headline `Te ha tocado regalar a {Nombre}` on `/reveal`. One Display element per screen, maximum |
| Heading (20/600/1.2) | Screen titles and section titles: `Tus preferencias`, `Guía de Tallas`, `Sala de espera`, `Sus preferencias`, `Tu pedido`, `Precios de referencia`, `Panel del Admin`. The `{filled} de {total}` fraction on `/admin` is also Heading |
| Body (16/400/1.5) | Every form value, every list row, every table cell, every notice body, the recipient's name inside the Display headline |
| Label (14/400/1.5) | Form labels, helper text, inline validation errors, badges, counts, table column headers, sub-captions, the privacy and trust notes |

Additional rules:

- **Table column headers are 14px / 600** (`<th scope="col">`) — the only non-role use of weight 600, and the only way a header is distinguished.
- **No text smaller than 14px anywhere.** `text-xs` and `text-[13px]` are defects.
- **All form controls render at 16px (`text-base`) even though their label is 14px** — this is what stops iOS from zooming the viewport on focus. The label is a separate element, not a placeholder substitute.
- **`tabular-nums`** on: the price table, the Admin `{filled} de {total}` fraction, the progress-bar labels, and the lobby count. Digits must not jitter while the numbers change under realtime updates.
- **Long text:** `break-words` on every element that renders user-supplied text (participant names, team strings, printed names, the recipient's name). **`truncate` is forbidden on user data** — a truncated recipient name in a gift app is a correctness bug, not a style choice.
- Font family: Tailwind's default system stack. If a token is declared for it, it must resolve to `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` — no downloaded font.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` (slate-50) | Page background on all five routes; the surface behind every card |
| Secondary (30%) | `#FFFFFF` (white) with a 1px `#E2E8F0` (slate-200) border | Cards, the size-guide tables, the price table, the modal surface, list rows |
| Accent (10%) | `#4F46E5` (indigo-600) | Reserved list below — nothing else may use it |
| Destructive | `#DC2626` (red-600) | The irreversible draw confirmation only (the confirm button inside `DrawConfirmDialog`) |
| Warning / notice | `#B45309` (amber-700) on `#FFFBEB` (amber-50) with a `#FCD34D` (amber-300) border | The D-16 Player/XXXL non-blocking notice and the D-12 size-guide anomaly notes — and nothing else |

Foreground tokens: primary text `#0F172A` (slate-900); secondary/helper text `#475569` (slate-600); text on accent `#FFFFFF`; border default `#E2E8F0` (slate-200); border focused `#4F46E5` (indigo-600).

State tokens:

| State | Value | Usage |
|-------|-------|-------|
| Disabled | `#E2E8F0` background, `#94A3B8` text, `cursor-not-allowed` | Any `disabled` button or control, always paired with `aria-disabled` |
| Loading skeleton | `#E2E8F0` with `animate-pulse` + `motion-reduce:animate-none` | Every loading placeholder (lobby rows, admin rows) |
| Error surface | `#FEF2F2` (red-50) background, `#FECACA` (red-200) border, `#991B1B` (red-800) text | Inline error `Notice` — deliberately distinct from the solid Destructive button so "this failed" never reads as "press this to destroy" |
| Success / status | `#ECFDF5` (emerald-50) background, `#A7F3D0` (emerald-300) border, `#065F46` (emerald-800) text | Submit success, download success, "todos los pedidos guardados" |
| Progress track / fill | track `#E2E8F0` (slate-200), fill `#4F46E5` (indigo-600) | The `/admin` progress bar only |

**Accent reserved for — exhaustive list. Nothing outside it may use indigo:**

1. The **single primary CTA of each screen**: `Entrar` (`/`), `Unirme al evento` (`/preferences`), `Empezar Sorteo` (`/lobby`, Admin only), `Guardar pedido` (`/reveal`), `Descargar Pedidos` (`/admin`). Solid indigo-600 fill, white 16px text, `rounded-lg`, `h-11`.
2. The **`Empezar Sorteo`** Admin-only button (same solid treatment — it is the phase's one high-stakes action).
3. The **progress-bar fill** on `/admin`.
4. The **selected `Size` chip** in the order form's talla control.
5. The **focus ring** on every focusable control: `focus-visible:ring-2 focus-visible:ring-indigo-600 focus-visible:ring-offset-2`.

**Explicitly NOT accent** (named so the executor cannot drift): secondary buttons (`Guía de Tallas`, `Reintentar`, `Cancelar`, `Volver a entrar`) are white with a slate-300 border and slate-900 text; links are slate-900 with an underline; badges (`Admin`, `Pendiente`, `Guardado`) are slate-100/slate-700; the D-16 notice and the D-12 anomaly notes are amber; the draw confirmation's confirm button is red-600; table headers, helper text and dividers are slate.

Contrast: every pair above meets WCAG 2.2 AA at its size — white on indigo-600 ≈ 6.3:1, slate-900 on slate-50 ≈ 17:1, amber-700 on amber-50 ≈ 5.6:1, red-800 on red-50 ≈ 7.2:1, emerald-800 on emerald-50 ≈ 7.4:1, slate-600 on white ≈ 5.6:1. Amber-700 (not amber-500/600) is required for the notice text precisely to hold that ratio.

**Dark mode: out of scope for Phase 1.** No `prefers-color-scheme` handling and no `dark:` variants — declared here so the executor does not half-implement it.

### Structural rules carried from research

- **`src/lib/` is the only directory allowed to import from `firebase/*`.** A reviewer must be able to see every query the app can issue by reading one directory.

- **No component builds a Tailwind class from a string** (`bg-${x}-500`) — Tailwind v4 scans literal class names only (research Pitfall 15). Condition → complete literal class name via a lookup object.

## Surface & Interaction Contracts

Five routes, seven surfaces, all mobile-first at 360×640. Nothing in this phase requires horizontal scrolling at 320px.

### S1 — Entrada · route `/` · `pages/EntryPage.tsx`

**Purpose:** capture the name and nothing else. No Firestore write happens on this screen.

**Layout:** `Screen` → app name (Display) → one-line value prop (Body, slate-600) → one `Card` containing one `Field` and the primary CTA.

**Elements**

| Element | Contract |
|---------|----------|
| App name | Display, `SecretKit` |
| Value prop | Body, `Amigo invisible entre amigos. Solo necesitas tu nombre.` |
| `Field` | label `Tu nombre`; `Input` with `autoComplete="name"`, `autoFocus`, `maxLength={40}`, `enterKeyHint="go"`, `type="text"` |
| Helper | `Solo necesitas tu nombre. Sin contraseñas.` |
| Primary CTA | `Entrar` — full width on `<sm` |

**Interaction contract**

1. Wrapped in a real `<form>` so Enter submits.
2. On submit: trim the value → empty ⇒ inline error, focus stays in the input.
3. Duplicate pre-check: `getDocs(participants where nameNormalized == normalizeName(name), limit 1)`. Taken ⇒ render the duplicate error in the form's error slot and keep focus in the name input. **Never auto-suffix, never append a number** (D-02).
4. Free ⇒ `saveIdentity({ uid, name })` to `localStorage`, then `navigate('/preferences')`.
5. **No `participants` document is created here.** The rules assert `size in ['S','M','L','XL','XXL','XXXL']` on `create`, so a participant document cannot exist without a size — which is why the join happens on S2 and why a half-joined participant is impossible by construction. This is a contract, not an implementation detail: the executor must not "fix" it by writing an early document.

**States:** loading (`Entrar` → `Entrando…` + `aria-busy`), error-duplicate, error-generic (`No hemos podido unirte al evento.` + `Reintentar`), and the auth-failure variant of the generic error. `FullScreenSpinner`/`Preparando…` covers app boot only.

### S2 — Preferencias · route `/preferences` · `pages/PreferencesPage.tsx`

**Purpose:** collect the required size and the optional team preferences, and perform the actual join.

**Layout:** `Screen` → Heading `Tus preferencias` → identity recap line → one `Card` with three fields + the size-guide trigger → sticky bottom primary CTA.

**Elements**

| Element | Contract |
|---------|----------|
| Identity recap | Body at 14px: `Entrarás como {nombre}` with a `ghost` `Cambiar nombre` action that clears the pending name and returns to `/` |
| Talla `Select` | label `Tu talla`; **required**; options S, M, L, XL, XXL, XXXL from `SIZES` |
| Equipos preferidos | label `Equipos que te gustan`; `Input`, optional, `maxLength={200}` |
| Helper (liked) | `Opcional. Escríbelos separados por comas.` |
| Equipos prohibidos | label `Equipos que NO quieres`; `Input`, optional, `maxLength={200}` |
| Helper (forbidden) | `Opcional. Quien te regale evitará estos equipos.` |
| Size guide trigger | `secondary` full-width button, locked label `Guía de Tallas`, opens S3 |
| Primary CTA | `Unirme al evento` — sticky at the bottom of the viewport on `<sm`, inline at `≥sm` |

**Interaction contract**

1. Submit runs `joinEvent(uid, name, { size, likedTeams, forbiddenTeams })` — the research's three-step shape: pre-check query → bootstrap-or-join `runTransaction` → post-commit rollback on collision.
2. Size unselected ⇒ block the submit, inline error on the select, focus the select. The CTA itself is **never disabled for validation** — only while submitting.
3. On success ⇒ `navigate('/lobby')`.
4. Re-entering with an existing participant document (refresh, back button) ⇒ the session already resolves to the lobby; S2 renders only for the `!hasPreferences` branch.

**States — four distinguishable failures, each with its own copy**

| Cause | Copy |
|-------|------|
| Duplicate name (pre-check) | `Ese nombre ya está en uso en el evento. Prueba con otro.` |
| Duplicate name (post-commit race) | `Ese nombre acaba de ser usado por otra persona. Prueba con otro.` |
| Event already drawn | `El sorteo ya se ha realizado: el grupo está cerrado.` |
| Network / unknown | `No hemos podido unirte al evento.` + `Reintentar` |

All four render in the form's error slot with the fields still editable. For the two duplicate cases the recap's `Cambiar nombre` returns to S1.

### S3 — Guía de Tallas (modal) · `components/SizeGuideModal.tsx`

**Trigger:** the `Guía de Tallas` button on S2, plus a small `secondary` trigger beside the talla `Select` on S6. Same modal, same content, same title both times.

**Title (locked):** `Guía de Tallas`

**Body order is fixed:**

1. `Versión Fan` — columns: Talla · Equivalencia · Largo (cm) · Altura (cm) · Peso (kg). Six rows, values verbatim from `domain/sizeGuide.ts` (equivalences `P=`, `M`, `G`, `GG`, `XG`, `2XG`).
2. `Versión Player` — columns: Talla · Largo (cm) · Ancho (cm) · Altura (cm) · Peso (kg). Five rows, values verbatim. **The largest row is `2XL`, rendered exactly as the spec has it.**
3. Three amber `Notice` rows (`tone="warning"`):
   - `La camiseta Retro usa la tabla de la Versión Fan.`
   - `En la Versión Player, la tabla del proveedor llega hasta 2XL; no hay equivalencia para XXXL.`
   - `En la Versión Player, M y L comparten el mismo rango de peso en los datos del proveedor.`

The anomalies are **rendered literally and flagged, never corrected** (D-12 + `REQUIREMENTS.md`:88). No value may be edited, normalised, or hidden to make the table look consistent.

**Responsive contract (the explicit Phase-2 concern, built correctly now):**

- `< sm` (640px): each table becomes **one card per size**, titled with the talla, containing a `<dl>` of the four/five labelled values. No horizontal scrolling, no text below 14px, no shrunken cells.
- `≥ sm`: a real `<table>` with `<caption>` and `<th scope="col">`.
- The dialog's inner surface is `max-h-[85vh] overflow-y-auto` so the close button is never scrolled off-screen on a short phone.

**Interaction:** `<dialog>.showModal()`; `Esc` and the close button both dismiss; background inert; focus returns to the trigger. This is static reference content — there is no loading, empty or error state.

### S4 — Lobby · route `/lobby` · `pages/LobbyPage.tsx`

**Purpose:** the realtime roster, and (for the Admin only) the one action that starts the draw.

**Layout:** `Screen` → Heading `Sala de espera` → count line → participant `Card` list → minimum-3 `Notice` → Admin block.

**Elements**

| Element | Contract |
|---------|----------|
| Count line | `{n} participante` / `{n} participantes` — explicit singular/plural, `tabular-nums`, `aria-live="polite" aria-atomic="true"`, followed by `La lista se actualiza sola.` at 14px slate-600 |
| Participant list | `ParticipantRow` per participant, ordered by `nameNormalized` (never by `joinedAt` — `serverTimestamp()` is null in local snapshots and would mis-sort the just-joined row on that client) |
| Admin badge | On the row whose `uid === event.adminUid` |
| Own row | Suffixed `(tú)` so a user can locate themselves in a long list |
| Minimum-3 notice (Admin) | amber `Notice`: `Necesitas al menos 3 participantes para sortear. Faltan {3-n}.` |
| Minimum-3 notice (participant) | amber `Notice`: `El sorteo necesita al menos 3 participantes. Aún faltan {3-n}.` |
| Admin block | Rendered **only** when `uid === event.adminUid`. Primary button, locked label `Empezar Sorteo`, `disabled` while `n < 3`. The adjacent notice above it is the explanation — a disabled button never has to explain itself, and the reason is always on screen. |
| Non-admin placeholder | Where the button would be, a Body line: `Cuando el Admin empiece el sorteo, aparecerá aquí a quién regalas.` |
| Admin panel link | `secondary` link/button `Panel del Admin` → `/admin`. There is no global nav or tab bar in Phase 1; this is the only cross-route affordance besides the redirects |

**Interaction contract**

1. `onSnapshot` on `participants`, ordered by `nameNormalized`; unsubscribe returned from the `useEffect` (research Pitfall 8).
2. When `events/main.status` flips to `drawn`, **every connected client is redirected to `/reveal`** from the session's `eventStatus` push. No polling, and no copy anywhere says "recarga la página".
3. `Empezar Sorteo` opens `DrawConfirmDialog` (never `window.confirm`).
4. The draw itself (`runDraw`) is out of UI scope beyond the states below — the button shows a loading state until the transaction settles, and an already-`drawn` event is a silent no-op that redirects.

**DrawConfirmDialog (the phase's only destructive confirmation)**

| Element | Copy |
|---------|------|
| Title | `Empezar Sorteo` |
| Body | `Se sorteará entre {n} participantes. Nadie verá quién regala a quién y no se puede deshacer.` |
| Confirm | `Empezar el sorteo` (`danger` variant) |
| Cancel | `Cancelar` (`secondary`, initial focus) |

The body **must name the participant count** (D-10), and initial focus goes to `Cancelar` so a mis-tap on the lobby button cannot cost an accidental, irreversible draw. While the transaction is in flight the confirm button is `loading` and both buttons are disabled — the only defence the UI offers against a double-tap, on top of the transaction's own idempotency.

**States:** loading (3 skeleton rows + `Cargando participantes…`), empty (`Todavía no hay nadie en la lista.` / `En cuanto alguien entre, aparecerá aquí.` — transient, a snapshot with zero docs), error (the Firestore taxonomy in S8, rendered in the list slot), populated, overflow, zero-one-many.

### S5 — Revelar · route `/reveal` · `pages/RevealPage.tsx`

**Gating:** renders only when `eventStatus === 'drawn'`; anything else redirects via `App.tsx`. Route guards are UX — the rules are the access control.

**Layout, top to bottom:**

1. **Display headline — locked literal copy:** `Te ha tocado regalar a {Nombre}`.
   `{Nombre}` is rendered in a `<strong>` at the same 28px/600. The line wraps to at most 3 lines at 320px and is **never truncated**. If the name itself exceeds the available width it wraps (`break-words`), it does not overflow.
2. **Recipient preferences `Card`** — Heading `Sus preferencias`, then three labelled rows:
   - `Talla` → the literal size (`S`…`XXXL`)
   - `Equipos que le gustan` → the stored string
   - `Equipos que NO quiere` → the stored string
   Each value is Body with `break-words`. **An empty preference renders `Sin indicar`** — never a blank row, never a hidden row. "This person stated no preference" is information the giver needs (D-14), so the row is always present.
3. **Privacy line** — 14px slate-600 immediately under the headline: `Solo tú puedes ver a quién regalas. Nadie más, tampoco el Admin.`
   This is precise and defensible: the rules genuinely deny `list` on `assignments` to everyone including the Admin, and no participant can read another's pairing. It deliberately does **not** claim absolute privacy (the Firebase project owner can read Firestore by console — the accepted, documented limit). Phase 1 must not overclaim in UI copy.
4. **Order section** — Heading `Tu pedido` + `JerseyOrderForm` (S6).

**States:** loading (`Buscando a quién regalas…` + one skeleton `Card`), error (assignment fetch failure — the S8 taxonomy), and the **assignment-missing** state: `eventStatus === 'drawn'` but `getDoc(assignments/{uid})` returns nothing ⇒ error Notice `No encontramos tu asignación.` + Body `Vuelve a la sala de espera e inténtalo de nuevo.` + `secondary` action `Ir a la sala de espera`.

**Hard rule:** the only read used here is `getDoc(assignments/{uid})` by document id, then `getDoc(participants/{recipientUid})`. **No query over `assignments` may exist anywhere in the app** — the rules deny `list`, so it would fail with `permission-denied` for everyone, including the Admin, and it is broken code rather than merely unsafe.

### S8 — Cross-cutting states and the restore path

**App boot.** `FullScreenSpinner` + `Preparando…` while the identity resolves. **No route may ever show a blank screen before the first server response**, and no loading state may spin forever — every one is bounded by an error state below.

**Redirect-by-state (`App.tsx`), which is also the "already joined / refreshed" restore contract:**

| Condition | Destination |
|-----------|-------------|
| No identity, or identity without a stored name | `/` (S1) |
| Identity present, no `participants/{uid}` document | `/preferences` (S2) — this is the "entered the name but never finished joining" branch, and it is exactly the `!hasPreferences` case, so the restore path is correct by construction |
| Identity present with a participant document, `status === 'lobby'` | `/lobby` (S4) |
| Identity present, `status === 'drawn'` | `/reveal` (S5) |
| Unknown path (`*`) | the same computed destination |

**Identity lost.** Two reachable causes: `localStorage` cleared, or the Auth session gone (silent re-sign-in then yields a **new** `uid`, so the old participant document no longer matches).

- Copy: `No encontramos tu identidad en este evento.` + Body `Vuelve a entrar con tu nombre. Si ya estabas dentro, avisa al Admin.` + `secondary` action `Volver a entrar` (clears the stored identity, returns to S1).
- When `status === 'drawn'` the transaction refuses the re-join, so the same state appends: `El sorteo ya se ha realizado; no se puede volver a entrar.` and the `Volver a entrar` action is replaced by a plain explanation (there is nothing the user can do — that is honest, and MGMT-02/MGMT-03 are deferred).

**Firestore error taxonomy → copy.** Rendered as an error `Notice` in the affected surface's slot:

| Error code | Copy | Retry action |
|-----------|------|--------------|
| `permission-denied` | `No tienes permiso para ver esto.` | none — a retry cannot help |
| `unavailable` (offline) | `Sin conexión. Vuelve a intentarlo cuando recuperes la red.` | `Reintentar` |
| `resource-exhausted` (quota) | `Hemos alcanzado el límite de consultas por hoy. Inténtalo más tarde.` | none |
| `unavailable` during a write | `Sin conexión. El pedido no se ha guardado.` | `Reintentar` |
| `deadline-exceeded` / unknown | `Algo ha ido mal.` | `Reintentar` |
| Unhandled render error | `Algo ha ido mal.` + `Recargar` | `ErrorBoundary` |

**No optimistic UI in this phase.** Every mutation awaits its write and then shows a bounded loading state. That is deliberate: the product's whole promise is that a pairing is never shown before it exists.

## Accessibility & Responsive Rules

- **Mobile-first; the only breakpoint used in Phase 1 is `sm` (640px).** Design at 360×640; must not require horizontal scroll at 320px.
- **Touch:** every interactive target ≥ 44×44px, with ≥ 8px between adjacent tappable rows.
- **Inputs render at 16px** (`text-base`) to prevent iOS zoom-on-focus; labels are separate 14px elements, never placeholder-only.
- **Forms:** real `<form>`, `<label for>` on every control, `<button type="submit">`, Enter submits.
- **Focus:** a visible ring on every focusable element (`focus-visible:ring-2 focus-visible:ring-indigo-600 focus-visible:ring-offset-2`); the modal returns focus to its trigger on close.
- **Semantics:** exactly one `<h1>` per screen; the size-guide tables use `<caption>`/`<thead>`/`<th scope="col">`, and their `<sm` card fallback uses a `<dl>` per size.
- **Live regions:** `role="status"` for the D-16 notice, the submit success, the download success and the lobby count; `role="alert"` **only** for field-level validation errors.
- **Motion:** exactly one animation exists in the phase (the skeleton `animate-pulse`), always with `motion-reduce:animate-none`.
- **Language:** `<html lang="es">`.
- **Dark mode:** out of scope and not partially implemented.
- **Print:** out of scope — the deliverable is a downloaded file, not a print view.

- **Real-time.** The lobby is `onSnapshot`-driven and a status flip to `drawn` must move every connected client to `/reveal` without a manual refresh. No copy may instruct the user to reload.
- **Offline.** Firestore transactions fail while offline, so a join or a draw attempted offline must surface the `unavailable` copy and must not leave a half-written local state. The lobby may legitimately show its last cached snapshot; the write paths must never pretend to have succeeded.
- **No optimistic UI.** Every mutation awaits its write and then shows a bounded loading state. Deliberate: a pairing must never be displayed before it exists.
- **Accessibility breadth.** WCAG 2.2 AA for every control in this phase — contrast, visible focus, 44px targets, label association, live regions, `motion-reduce` on the one animation. i18n and RTL are out of scope (single language, `lang="es"`).
