<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → /admin/setup | Untrusted input (secret) crosses here; validated against VITE_ADMIN_SECRET in env |
| Client → Firebase Auth | Anonymous sign-in — no user credentials, but establishes uid for rules |
| Client → Firestore (events/main create) | Admin creates event document; rules enforce adminUid = request.auth.uid |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | /admin/setup secret input | medium | mitigate | Secret compared to VITE_ADMIN_SECRET from env (not in bundle); simple string compare; no rate limiting needed for private event |
| T-03-02 | Tampering | events/main creation | high | mitigate | Firestore rules: create requires adminUid == request.auth.uid, status == 'lobby'; adminUid immutable on update |
| T-03-03 | Information Disclosure | VITE_ADMIN_SECRET in bundle | low | mitigate | VITE_ vars are embedded in client bundle by Vite; this is accepted per D-01 (secret is UI gate only, not cryptographic). Document in README trust contract. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS] |

</threat_model>
